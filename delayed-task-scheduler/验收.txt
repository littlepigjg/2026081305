## verify_cmds

### task-slice-cleanup-001

#### 复现步骤

从零开始：进入项目根目录，执行 `export GOTOOLCHAIN=local`。启动服务（`go run ./cmd/server/main.go`）。提交 5 个任务（ID 为 A~E，延迟 1 秒），等待 2 秒使其变为 `ready` 状态。连续发送 `DELETE` 请求删除 B、C、D。然后立即发送 `GET /api/v1/task/ready` 拉取剩余任务。未修复时，服务会因索引越界 panic 并返回 500 错误；修复后应正常返回 A 和 E。

#### verify_cmds

```bash
#!/bin/bash
set -e

# 环境准备：切换到项目根目录
cd delayed-task-scheduler
export GOTOOLCHAIN=local

# 构建并启动服务
go build -o server ./cmd/server/main.go
./server &
SERVER_PID=$!
sleep 2

# 前置准备：清理可能遗留的任务
curl -s -X DELETE http://localhost:8080/api/v1/task/A || true
curl -s -X DELETE http://localhost:8080/api/v1/task/B || true
curl -s -X DELETE http://localhost:8080/api/v1/task/C || true
curl -s -X DELETE http://localhost:8080/api/v1/task/D || true
curl -s -X DELETE http://localhost:8080/api/v1/task/E || true

# 提交5个任务（使用不同ID）
for id in A B C D E; do
  curl -s -X POST http://localhost:8080/api/v1/task \
    -H "Content-Type: application/json" \
    -d "{\"id\":\"$id\",\"payload\":\"payload_$id\",\"delay_seconds\":1}" > /dev/null
done

# 等待1秒让任务变为ready
sleep 2

# 触发缺陷：连续删除3个任务（B、C、D）
echo "Deleting tasks B, C, D sequentially..."
for id in B C D; do
  curl -s -X DELETE http://localhost:8080/api/v1/task/$id
done

# 验证结果：拉取剩余任务（预期返回 A 和 E）
echo "Fetching ready tasks..."
RESPONSE=$(curl -s http://localhost:8080/api/v1/task/ready)
if echo "$RESPONSE" | grep -q "A.*E"; then
    echo "GREEN: Ready tasks fetched successfully, server stable."
else
    echo "RED: Server panicked or returned invalid response. Response: $RESPONSE"
fi

# 静态检查（确认无明显 vet 问题）
go vet ./... && echo "GREEN: go vet passed" || echo "RED: go vet issues found"

# 清理
kill $SERVER_PID
wait $SERVER_PID 2>/dev/null || true
```

#### success_criteria

- **未修复时**：执行脚本后输出 `RED: Server panicked...`，或服务进程退出；日志中可见 `panic: runtime error: index out of range`。
- **修复后**：输出 `GREEN: Ready tasks fetched successfully`，`go vet` 无警告，进程正常处理请求。

### 复现路径

1. 启动服务：`go run ./cmd/server/main.go`。
2. 提交 5 个任务：`POST /api/v1/task`（payload 分别为 A、B、C、D、E）。
3. 依次删除任务 B、C、D（`DELETE /api/v1/task/B、C、D`）。
4. 拉取剩余任务：`GET /api/v1/task/ready`。
5. 观察服务是否 panic 或返回错误。
